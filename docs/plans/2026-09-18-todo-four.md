# TODO 四條 Implementation Plan

**Goal:** 卸除 caveman，並把三條〔cuts〕照已批准的設計落地、關掉四個 `TODO.md` 條目。
**Architecture:** 六個 task。T1、T6 在主 session 跑：T1 動使用者的設定，T6 關 `TODO.md`。T2–T5 檔案互不相交，交給 implementer。四條 cuts 都是不改行為的刪減，證據是改前改後同一組測試都綠、grep 計數歸零、`skills-check.js` 的輸出逐字不變。
**Tech Stack:** Node 內建模組，CommonJS，`node --test`；沒有任何依賴。這台機器是 Node v24.9.0。
**Spec:** [2026-09-18-todo-four-design.md](2026-09-18-todo-four-design.md)

## Global Constraints

- `package.json` 沒有 `dependencies`，也沒有 `devDependencies`，`test` 是 `node --test`。不得新增依賴，只用 Node 內建模組。也沒有 `engines` 欄位。
- 模組是 CommonJS，開頭 `'use strict';`。縮排跟著檔案本身：`lib/`、`scripts/station.js`、`scripts/skills-check.js`、`scripts/stage-registry.js` 是四格，`scripts/sessions.js` 與 `tests/` 是兩格。`scripts/sessions.js` 的 require 不帶 `node:` 前綴，`lib/registry.js` 的帶；照各檔原樣。
- `assets/station/station.js` 是瀏覽器端的檔案，寫法是 `var` 與 `function`；不引入 `const` 或 arrow function。
- `tests/source.test.js`：每個 export 出去的名字都要有東西 import。這次新增的 helper 一律不 export。
- `node scripts/docs-check.js` 要 exit 0。搬動程式碼會讓 `path:line` 位移，而且 docs-check 只確認那一行存在，不確認內容對得上。所以每個 task 都附上一份指進它自己檔案的引用清單，逐條對照：先用 `git show HEAD:<file> | sed -n '<N>p'` 看原本指的是哪一行，再把數字改成那段程式碼現在的行號。`docs/reports/`、`docs/decisions/`、`docs/judgements/`、`docs/archive/` 的引用不動。
- `node scripts/todo-check.js` 要 exit 0。
- 實作者只跑自己的測試檔，不 commit。T2–T5 最後一步的 commit 指令由主 session 執行：整組回來、`npm test` 全綠之後，照 task 順序跑。多個實作者共用同一個工作樹，commit 一律用 `git commit -o <paths>`，只提交那個 task 的檔案。
- Windows：含反斜線的內容走 Write／Edit，不走 shell heredoc；不跑 `find /`。
