# Dispatch Implementation Plan

**Goal:** replace a blanket prohibition on delegating pipeline stages with a
principle, make `survey` dispatch readers instead of asking permission to read,
and make every plan task declare its dispatch shape and model tier.

**Architecture:** four prose surfaces and two rule arrays. No new script, no new
document, no new flag. `lib/stages.js` carries the two injected rules that change;
`lib/render.js` carries one line for the subagent brief; four `SKILL.md` files and
two `docs/` pages carry the reasoning. Nothing in code reads a `**Dispatch:**`
line — it is prose in a plan file, read by whoever runs the loop.

**Tech Stack:** Node 24, `node --test`, zero dependencies. Tests are
`node:test` + `node:assert/strict`.

**Spec:** [docs/plans/2026-08-26-dispatch-design.md](2026-08-26-dispatch-design.md)

## Global Constraints

Generated from `node scripts/map.js`, `package.json` and the assertions in
`tests/`. There is no `CLAUDE.md` in this repository, so the conventions below
come from the suite rather than from a conventions file.

- **No dependencies.** `package.json` has no `dependencies` or `devDependencies`
  key and `"private": true`. Nothing may be added.
- **Test command is `npm test`**, which is `node --test`. `node --test tests/`
  fails with `MODULE_NOT_FOUND` — do not use it.
- **Indentation:** 4 spaces in `lib/`, `hooks/` and `scripts/`; **2 spaces in
  `tests/`**. Match the file you are in.
- **`rulesFor(<stage>).join('\n').length < 2000`** — `tests/stages.test.js:83`.
  Current: `survey` 1615, `plan` 1525, `build` 1928. The `ALWAYS` block is 665 of
  each.
- **`ALWAYS.length <= 4`** — `tests/stages.test.js:58`. It holds 4. Nothing may be
  added to it.
- **Every stage keeps `rules.length >= 3` and every rule `length > 20`** —
  `tests/stages.test.js:43-45`.
- **The subagent brief is under 1400 characters** — `tests/brief.test.js:117`.
  Current: 615.
- **`TODO.md` entries are at most 200 characters** — `scripts/todo-check.js:28`.
- **A skill's `name` equals its directory and its `description` exceeds 60
  characters** — `tests/skills.test.js:37,47`.
- **No live page may contain `--scope`** — `tests/skills.test.js`, last test.
- **`scripts/survey.js`:** `DEFAULT_MAX = 25` per section; `--all` sets the cap to
  `Infinity`; `--tree` adds the directory section. A capped section prints the
  literal `... and N more, not listed`; a truncated walk prints `the walk stopped
  at N files`.
- **Commit style:** lower-case type prefix, then a colon and a phrase —
  `feat:`, `docs:`, `chore:`, `fix:`. Taken from `git log`.
- **Do not touch** `docs/decisions/fankeel-shell.md` (role `decision`: written
  once, not maintained) or anything under `docs/archive/`.

````markdown
### Delegate the reading, never the filtering

The tempting version is to run whole stages in background agents to keep the
context small. For one kind of work, measured on this repository, that is the
wrong tool for the thing it is aimed at:

```
npm test, full output             49,074 characters
the two lines that decide it          24 characters
```

A subagent would read all 49,074 in a context that gets thrown away, and cost its
own system prompt to do it. `| grep -E '^ℹ (pass|fail)'` costs nothing and is
2,045 times better. **What stacks up a context is raw output arriving in it, not
work being done** — and the fix for that is at the source, which is what every
stage's `Output:` rule is for.

But that measures **filtering output you have already produced**. It says nothing
about work not yet done, where the arithmetic runs the other way: a dispatched
reader opens the files, follows the dead ends and reads the failed runs in a
context that is thrown away, and what lands here is the answer. Measured on one
fan-out of four readers over another plugin's skills: 240,881 tokens spent, about
4,000 characters returned, 121 seconds of wall-clock rather than 352 because they
went out in one response.

| | |
|---|---|
| **delegate** | wide reading with a narrow answer — *read these six documents and say whether any contradicts the code*. A judgement, so no filter can pick it out |
| **do not delegate** | anything a pipe already removes. One command's output is not worth a system prompt |

Three rules that make it work, each of which fails silently when missed:

- **Several dispatches in one response run at once.** One per response runs them
  in sequence — the cost of parallelism with none of it.
- **Always pass the model.** An omitted model inherits this session's, which is
  usually the most capable and most expensive one available.
- **Spot-check the results against each other.** Independently dispatched agents
  share a prompt style and a model, so they make correlated mistakes that reading
  each summary on its own will not catch.

Which stages dispatch is not settled here. `survey` dispatches readers when its
own scanner reports it did not list everything; `build` dispatches per task, and
the plan's `**Dispatch:**` line is where that was decided.
````
