# Ready 兩條 Implementation Plan

**Goal:** 鎖等待測試不再因子程序啟動慢而偶發紅；讀 POST body 與處理未知參數的重複段各抽成 `lib/` 的一個 helper。
**Architecture:** 測試的 releaser 在開始等待前先往 stdout 寫一行 `started`，父程序讀到才呼叫 `addClaim`，讓 1 秒上限的計時不含 node 的啟動時間。`lib/body.js` 的 `readBody` 取代 `scripts/tune.js` 的內嵌讀取與 `scripts/station.js` 的 `readBody`，用 `destroyOnOverflow` 保住兩邊各自的超量行為；`lib/cli.js` 的 `parseArgsOrExit` 取代 `scripts/station.js` 與 `scripts/render.js` 兩段一樣的 catch。
**Tech Stack:** Node 內建模組（`node:util` 的 `parseArgs`、`node:stream`、`node:child_process`），`node --test`；`package.json` 沒有任何依賴，也不加。
**Spec:** [design.md](../../.fankeel/build/task-20260923T032052/design.md)（本機、gitignored；做法在對話裡批准，session c6623f3b-9c94-4762-92c8-b2fffc3b49f5）

## Global Constraints

- 不加依賴：`package.json` 沒有 `dependencies`，只用 Node 內建模組。
- `lib/`、`scripts/` 用四格縮排、`'use strict';` 開頭、CommonJS `require`／`module.exports`；`tests/` 用兩格縮排。
- 測試跑法是 `node --test <file>`；整套是 `npm test`（`node --test`）。implementer 只跑自己的測試檔。
- 錯誤訊息逐字不變：`<prog>: unknown argument <flag>`、exit 2 —— `tests/station-cli.test.js:298` 斷言 `/^station: unknown argument --bogus$/m`。
- 超量上限沿用 65536 字元，兩個呼叫端的行為都不變：tune 超量就 `req.destroy()` 不回應；station 超量就停止累加、照樣 resolve。
- 交付的 task 在同一個 commit 裡刪掉 `TODO.md` `## Ready` 裡對應的那條，並跑 `node scripts/todo-check.js`。
- commit 訊息用繁體中文、`test:`／`refactor:`／`docs:` 前綴，結尾照 session 的 attribution。
- `.fankeel/map.md` 不手改；`lib/` 新檔若要進 README 的目錄樹，land 時跑 `node scripts/map.js`。

'use strict';

// One POST body, as a string, capped.
//
// `scripts/tune.js` and `scripts/station.js` each read one, and past the cap
// they did different things on purpose: tune drops the connection without a
// reply, station keeps what it has and answers anyway. `destroyOnOverflow`
// keeps both rather than choosing for either.

function readBody(req, { max = 65536, destroyOnOverflow = false } = {}) {
    return new Promise((resolve) => {
        let text = '';
        req.setEncoding('utf8');
        req.on('data', (c) => {
            if (destroyOnOverflow) {
                text += c;
                if (text.length > max) req.destroy();
            } else if (text.length < max) {
                text += c;
            }
        });
        req.on('end', () => resolve(text));
        req.on('error', () => resolve(''));
    });
}

module.exports = { readBody };
```

'use strict';

// The `node:util` parser every script here uses, with the one refusal they
// share. `strict: true` is what refuses an unrecognised flag; the shapes it
// throws for — an unknown option, or a declared flag given no value — become
// `<prog>: unknown argument <flag>` and exit 2, the message and code
// `scripts/station.js` has always used, so nothing piping stderr sees a change.

const { parseArgs } = require('node:util');

function parseArgsOrExit(prog, argv, options) {
    try {
        return parseArgs({ args: argv, options, allowPositionals: true, strict: true });
    } catch (e) {
        const bad = /'(--?[a-zA-Z0-9-]+)/.exec(e.message);
        process.stderr.write(prog + ': unknown argument ' + (bad ? bad[1] : String(e.message)) + '\n');
        process.exit(2);
    }
    return undefined;
}

module.exports = { parseArgsOrExit };
```
