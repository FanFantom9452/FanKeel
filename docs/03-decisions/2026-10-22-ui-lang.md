# station、Pane、band 用同一個介面語言 ui.lang（10-22）

一句話：在 station 的地球選單切換語言，會寫進這台機器的 profile `ui.lang`，Pane 和 band 每次重畫都讀它，所以三處一起換成中文或英文，不用重開；原本的 `language` 改名 `model.lang`，只管 stage agent 寫報告和 gate 用的語言。

設計在 [99-archive/2026-10-22-ui-lang-design.md](../99-archive/2026-10-22-ui-lang-design.md)，計畫在 [99-archive/2026-10-22-ui-lang.md](../99-archive/2026-10-22-ui-lang.md)。

## 決定

- profile 分兩個鍵：`model.lang` 是模型寫字用的語言，`ui.lang` 是畫面語言，只收 `zh` 或 `en`，沒設就是中文。
- 舊檔裡的 `language` 仍當 `model.lang` 讀；`profile set language` 會被拒絕並指向 `model.lang`。
- `ui.lang` 只存在機器 profile：專案層寫入會被拒絕，專案檔裡有也不讀。
- station 選語言時 POST `/profile`（scope=machine），寫入成功才重新載入；失敗就不重載，顯示提示。頁面語言的順序是 profile、localStorage、瀏覽器。
- `hooks/pane-lang.ts` 放中英詞表並讀 `ui.lang`；`hooks/pane.ts` 每個 tick 讀一次，傳給 band、Pane 和 Desktop 圖。
- 英文第一列比較寬，Desktop 圖超寬時先拿掉「遠端」，再拿掉本站分鐘數。

## 為什麼

使用者要 Pane 和 band 跟著 station 的語言切換，而且要 profile 把介面語言和模型語言分開。存在機器 profile 是因為 Pane 和 band 跨專案共用，每個 tick 重讀就不需要通知機制，下一次重畫就換好。

## 放棄了什麼

- 沿用 `language` 一個鍵管兩件事：介面英文不代表報告也要英文。
- 專案層的 `ui.lang`：同一台機器的 Pane 跨專案，專案各設一個會互相打架。
- 用 localStorage 當唯一來源：hook 讀不到瀏覽器的 localStorage。
