# 路線進度只在那一站有在做事時呼吸（10-15）

一句話：監控站的六角圖示只在目前這一站真的有 agent 在跑、而且沒有問題在等你時才會呼吸；停在提問、或什麼都沒在跑時就靜止。Desktop 的路線圓點 10-16 起不再呼吸，見下面「10-16 改」。

## 決定

- 「有在做事」的判斷：這一站有 stage agent 的標記、標記不到 20 分鐘，而且沒有問題在等你回答。
- 監控站：伺服器端在每一列算出 `busy`，頁面據此給六角圖示加上 `live`，呼吸動畫只在 `live` 底下跑；減少動態的設定照樣讓它停。
- 子 agent 結束時送出的 `turn.complete` 不算你的回合結束。
- 10-16 改：Desktop 的 Pane 與 band 不再畫呼吸的 SMIL 擴散圈，也不再看回合。狀態改由形狀表示：還沒走到的站是灰色空心、目前這一站是空心加站色外框、走過的站是實心（`hooks/pane-svg.ts`）。使用者看了 band 的實際畫面後決定不要動畫。
- 終端機的 statusline 不做：它是文字，只在 Claude Code 呼叫時才重畫。

## 為什麼

使用者要的是一眼看出「現在這一站是不是真的在跑」。原本監控站的六角圖示不論有沒有在跑都在呼吸，等於沒有資訊。登記檔裡的 `updated` 只在每次送出 prompt 時更新，不是心跳，所以監控站只能用 stage agent 的標記判斷；Desktop 的 mod 收得到回合開始與結束的事件，可以多看一個訊號。

## 放棄了什麼

- 監控站那排舊的圓點（`routeDots`）：在現在唯一的 keel 外觀下根本不會畫出來，所以改的是六角圖示，不是它。
- 監控站在一般對話（沒有派 stage agent）時也呼吸：要讀主對話的 transcript 尾巴，成本和誤判都比這次的需求大。
- 等 Desktop 實機量過才做 Pane：使用者選了先發版再量（TODO pane-8），因為動畫跑不起來時那一圈是透明的，不會壞掉任何東西。
