# 監控站的連結直接開在要看的東西上（10-21）

首頁四塊的部分已由 [2026-10-22-station-live-home](2026-10-22-station-live-home.md) 改成「進行中」頁；一層導覽照舊。

一句話：chat 印出的連結會開一張只載入單一 session 的焦點頁，直接看到這一站要審的計畫或 gate；首頁縮成四塊，左側導覽只剩一層；背景 shell 會出現在監控站和 Pane 上。

設計與計畫在 [99-archive/2026-10-21-station-focus-design.md](../99-archive/2026-10-21-station-focus-design.md)。同一個任務也收掉了巡查找到的五條 TODO。

## 決定

- 新增 `/f/<session>/<分頁>` 焦點頁，只讀那個 session 自己的登記檔、交接檔、計畫和 ledger，不載入整份監控站資料。
- 伺服器把每個 session 的列和逐字稿位置快取起來，只有檔案的修改時間變了才重讀。
- 左側導覽只有一層：現在、Sessions、花費、文件；上面加一個 Ctrl+K 跳轉框。
- 首頁只留四塊：等你回覆的 session、正在跑的、TODO、今天與本週花費。其他卡片搬到各自的頁面，舊網址會導到新頁。
- profile 鍵 `station.link` 列出哪些站在 chat 只印交接檔路徑和連結，不印整份報告；監控站沒開時照舊印報告。
- 背景 shell 從逐字稿配對出來，讀輸出檔最後一段判斷還在跑還是已結束，最多顯示三列。

## 為什麼

使用者要的是點了連結就看到這一站要審的東西，而且每一頁都在 500 毫秒內出來。原本打開一個 session 要先下載 2.7 MB 的全站資料，再等約一秒的細節，總共約 2.6 秒。焦點頁只讀一個 session，不必等全站資料。chat 只印連結，可以少花輸出 token。

## 放棄了什麼

- 讓整個監控站變快就好、不另做焦點頁：全站資料再快也要讀所有 session，達不到開連結就看到要審內容的要求。
- 首頁的自訂版面編輯模式：拿掉了，四塊固定內容比可以拖拉的卡片更快找到東西。
- 舊的折疊式兩層導覽：拿掉了，每一頁都多一次點擊。
