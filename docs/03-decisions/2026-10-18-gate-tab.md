# 其他四道 gate 附 station 關卡頁（10-18）

一句話：survey、design、build、land 停在 gate 時，`scripts/await.js` 在 station 開著的情況下多印一行 `page: <url>#/s/<id>/gate`；session 頁多一個「關卡」tab，把那一站交回的報告排成一頁——發現、要改的檔、改了什麼、白話結案，問題浮在最上面，答案仍在 Claude Desktop 給。

這是「gate 附 station 頁」的第二刀，第一刀是 [plan gate 的計畫頁](2026-10-18-plan-gate-page.md)。設計與計畫在 [2026-10-18-gate-tab-design.md](../99-archive/2026-10-18-gate-tab-design.md) 與 [2026-10-18-gate-tab.md](../99-archive/2026-10-18-gate-tab.md)。

## 決定

- 四道 gate 共用一個「關卡」tab，依站別畫不同面板，不各開一個 tab：survey 與 build 精簡，design 與 land 詳細，plan 留在原本的「計畫」tab。
- 報告由新的 `lib/gatereport.js` 讀：那一站最新的 handoff 報告，group brain 的 `-g<N>` 檔也算；照各站自己的報告範本拆欄位，認不得的行原樣放在「報告其餘」，一行都不丟。
- land 的報告範本多一行 `白話:`，給不寫程式的人看，關卡頁把它放第一個。
- 「正在等你回答」只認兩個訊號：registry 的 `gateAt` 時戳，或 pending 檔裡有問題。報告剛好是這一站的，不算在等——group brain 在 build 中途寫的報告就是這種情形。
- 寬度不到 1000px 時拿掉 body 的最小寬度、收起側欄與搜尋，800px 的 pane 不必左右捲。

## 為什麼

計畫頁上線後，另外四道 gate 仍然只能在對話裡讀一大段報告再回答。把報告攤成一頁，回答前就看得到發現幾處、要改哪些檔、結案說了什麼。

## 放棄了什麼

- 四道 gate 各一個 tab：分頁太多，而且同一時間只會停在一道 gate。
- 從報告內文猜「是不是在等」：verify 抓到 build 中途的 group 報告會讓頁面誤顯示「等你回答」，所以改成只看 registry 與 pending 檔。
- mockup 裡 14 項報告沒帶的資料（各站花費長條、mockup 縮圖、模型色塊等）：這次不做，記在 TODO「關卡頁補報告沒帶的欄位」。

## 還沒驗的

- 被拒絕的 gate 會留下 `gateAt` 時戳，關卡頁在下一次真正作答前會誤顯示在等；記在 TODO「被拒的 gate 留下 gateAt」。
- 在 Claude Desktop 裡，先開的瀏覽器 pane 會出現在問題前面還是後面，仍沒有在真的 gate 上看到。
