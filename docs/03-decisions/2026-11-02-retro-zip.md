# retro-all 改成匯出 ZIP 回傳，不 push（11-02）

一句話：別人（例如教授）跑 `/fankeel-retro-all` 之後，不再把 session 包推進 repo，而是用 `record.js export` 打成一個 ZIP 傳回來；ZIP 裡有回顧報告、原始 session 包和一份環境清單，維護者用 `record.js import` 解開分析。

設計與計畫在 [99-archive/2026-11-02-retro-zip-design.md](../99-archive/2026-11-02-retro-zip-design.md) 與 [99-archive/2026-11-02-retro-zip.md](../99-archive/2026-11-02-retro-zip.md)。

## 決定

- retro-all 的關卡多一個選項「匯出 ZIP 回傳」。匯出寫到 `.fankeel/exports/`，匯入解到 `.fankeel/imports/<檔名>/`，兩個目錄都不進版控。
- ZIP 裡有 `report.md`、挑選的 `.jsonl.gz` 包和 `manifest.json`。清單只收白名單欄位：作業系統、fankeel 版本、Node 版本、專案的 Node 套件，用來判斷錯誤出在哪個環境。
- 隱私在匯出那一刻問匯出者（多選）：要不要記全域 Node 套件、要不要保留原始路徑。兩項預設都不勾，也就是不記全域套件，家目錄一律換成 `[HOME]`，包括 `/c/Users/<名字>` 與 JSON 跳脫過的反斜線寫法。
- 匯入會比對 sha256，已經有的同名包跳過；檔名帶 `..` 的項目拒收。
- ZIP 用自己寫的 `lib/zip.js`（寫入不壓縮，讀取支援 STORED 與 DEFLATE），不加任何相依。

## 為什麼

使用者不希望別人 push 到 repo，又需要拿到原始 session 才能分析。開 Gitea issue 再另外傳包要兩步，一個 ZIP 一步就夠。加上環境清單，是為了出錯時看得出是哪個系統、哪個版本。家目錄預設遮掉，因為路徑裡常帶著使用者名稱。

## 放棄了什麼

- 讓別人把包 commit 後 push（[2026-10-20-retro-bundle](2026-10-20-retro-bundle.md) 的做法）：這次改成回傳 ZIP，那一頁照日期保留。
- Gitea issue 回報加另外傳包：要兩步。
- 用 npm 的 zip 套件：專案沒有相依，手寫的容器夠用。
- 預設記錄全域套件和原始路徑：交給匯出者自己勾。
