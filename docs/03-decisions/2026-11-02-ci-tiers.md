# 測試分兩層、推送後讀 CI、plan 太大就拆組（11-02）

一句話：專案用一份 `.fankeel/suite.json` 宣告哪個目錄跑哪條測試、屬於日常還是 nightly，land 只跑日常層，推送後用 `ci-status.js` 讀一次 CI；plan 超過一個 context 時拆成一份索引加每組一份 plan；每一站問關卡前都要先寫報告。

設計與計畫在 [99-archive/2026-11-01-professor-ci-tiers-design.md](../99-archive/2026-11-01-professor-ci-tiers-design.md) 與 [99-archive/2026-11-02-professor-index.md](../99-archive/2026-11-02-professor-index.md)。

## 決定

- 分層宣告放在進版控的 `.fankeel/suite.json`（`daily`、`nightly`，每條帶 `dir` 與 `run`），不放 profile。沒有這個檔時，suite 照舊跑 `package.json` 的 `test`。
- nightly 只給範本 `assets/ci/nightly.yml`，由專案自己的 CI 排程；fankeel 不替任何專案寫 workflow。
- `ci-status.js` 只讀一次、不等、不擋 land。Gitea 認證依序試 `GITEA_TOKEN`、`git credential fill`，都不行就印 Actions 頁網址。token 只走 https，設了 `GITEA_URL` 就只送給那台主機；GitLab、Bitbucket、Azure 不發請求。
- `test-audit.js` 只列疑似失效與疑似重複的測試，不刪。比對重複時，字串裡的空白要保留。
- plan 拆組：設計分成兩組以上互不共用檔案的工作，且任一組超過 8 個 task，就寫一份索引（介面與相依）加每組一份 plan，build 依相依順序逐組跑。
- 每一站問關卡前，先把報告寫到 `.fankeel/build/task-<started>/<stage>.md`，`hooks/gate.js` 沒看到報告就拒絕；換站時 `task.js stage` 把上一站的報告提交到 records。
- 關卡頁與手機網址印在問題之前，選項裡不放。

## 為什麼

教授要 fankeel 能用在 Gitea 上的多目錄專案，並把慢的 E2E 移到 nightly。用一份宣告檔，專案自己說清楚哪裡跑什麼，不用從 CI 檔猜。ci-status 不擋 land，因為 CI 結果可能要好幾分鐘才出來，而 land 是使用者在等。token 範圍是 verify 發現的：原本會把 token 送給任何非 GitHub 主機，連 http 也送。

## 放棄了什麼

- 用 profile key 宣告分層：一個值裝不下多目錄、多指令。
- 動研究室既有的 RH 專案或替它寫 CI：使用者說不碰，只給範本。
- `test-audit` 自動刪除：只列出來，刪不刪由人決定；bench/ 對照組要不要跳過另記成 TODO。
- TODO 依 stage 分組顯示：那段逐字稿講的是已完成的 session 清單，條目已以 abandoned 關閉。
- 別名主機（`www.github.com`）也收進已知平台：與已裁定的殘留同一路徑，設 `GITEA_URL` 就能封住，沒有補。
