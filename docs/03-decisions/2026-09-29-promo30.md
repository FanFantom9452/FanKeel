# promo30 30 秒解說片（09-29）：決策紀錄

一句話：導覽引擎多了第二條 timeline `promo30`——30 秒、1800 格的龍骨造船解說片，給開發者看，中英兩版；頁面與錄影腳本都改成播 hash 指名的那一條，第一版 60 秒 reel 一格未動。

design 見 [../99-archive/2026-09-29-promo30-design.md](../99-archive/2026-09-29-promo30-design.md)，計畫見 [../99-archive/2026-09-29-promo30.md](../99-archive/2026-09-29-promo30.md)，引擎與錄影的說明見 [../90-agent/reference/station.md](../90-agent/reference/station.md)。

## 定了什麼

- 第一版 reel 先存成 v1：tag `tour-reel-v1`、MP4 複製到 `F:/ymlab/fankeel-videos/v1/`；第二版 tag `tour-reel-v2`、MP4 在 `F:/ymlab/fankeel-videos/v2/`（survey 與 build 的 gate，使用者答）。
- 概念從「龍飛來、捲曲、只剩骨頭」改成龍骨造船：龍的 spike 畫不好看，使用者從多個方案裡選了造船（design，使用者答）。
- 每個 stage 用真的元件表示——語言與檔案圖示、mockup 逐塊調整、audit 劃掉過期文件並把 plan 收進封存資料夾、land 收 worktree——不要全是文字（design，使用者依參考影片提）。
- 檔名 `assets/station/tour-keel.js`，不是 plan 寫的 `tour-promo30.js`：`scripts/station.js` 的靜態路由只放行 `tour(?:-[a-z]+)*`，而另一個 session 正佔著 `station.js`（build 的 gate，使用者答）。封存的 plan 與 design 保留舊名，當歷史。
- 配樂 `render(cues, frames)` 的長度跟著 timeline；reel 的配樂逐樣本不變。

## 量到什麼

- 全套 `npm test`：2424 過、0 失敗；`docs-check` 全部解析。
- 兩支 v2 影片各 1800 格、30 秒 AAC；zh 版 7 個 stage 抽格的點數都對，en 版沒抽（verify 記為沒查）。
- reel 配樂新舊渲染比對 2646000 個樣本 0 差異；兩個變異測試轉紅。

## 在哪裡回頭

- 使用者看完 v2：風格喜歡、右側動畫好，但左側直接畫一艘船太直白，也讓左邊顯得沒用——「還可以，但沒有戳到點」。下一步是 v3 的 design，從使用者自己說的重點出發，重做左側。
- 後段 U 形肋骨弧線糾結、小 logo 像梳子——TODO 的 `station-4`、`station-5`。
