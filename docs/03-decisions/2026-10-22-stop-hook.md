# 主控結束回合前先問一次 Stop hook（10-22）

一句話：主 session 在 stage 還沒走完、背景也沒有東西會叫醒它時想結束回合，`hooks/stop.js` 會擋下一次，要它先派下一步、跑 `await.js` 或問 gate。

原因的分析在 [2026-10-22-stage-agent-pause](../90-agent/judgements/2026-10-22-stage-agent-pause.md)，設計在 [99-archive/2026-10-22-stop-hook-design.md](../99-archive/2026-10-22-stop-hook-design.md)。

## 決定

- `hooks/stop.js` 掛在主執行緒的 `Stop` 事件，判斷寫在 `lib/stop.js` 的 `refusal`。
- 只在這些情況都成立時擋下：任務還在進行、有 stage、使用者沒被標成要離開，而且 transcript 裡沒有還沒收到通知的背景 Bash、非同步 Agent 或 SendMessage。
- 一次就好：同一次停止已經被擋過（`stop_hook_active`）就放行，所以真的在等使用者回答的回合，第二次就能結束。
- transcript 讀不到時一律放行。

## 為什麼

判官讀了十個 session 的紀錄：停頓的主因是主控回一句「等 X 好了再繼續」就結束回合，當時背景沒有任何東西會叫醒它；stage agent 本身 76 次都有正常交回。規則只在派工、SendMessage、沒帶路徑的完成通知這三種情況安排 `await.js`，其他情況沒有東西攔住它。

## 放棄了什麼

- 讓 `await.js` 寫下自己的 pid、用 pid 還活不活著判斷：要多改 `scripts/await.js`，而 transcript 裡的通知已經說了背景工作有沒有結束。
- 用 registry 的 `inflight` 標記判斷：那些標記會留著沒清（stage-agents-14），用它會讓 hook 該擋的時候放行。
- 已知的缺口另記在待辦「Stop hook 背景無通知永遠待回」：沒收到通知的背景工作會一直算待回，hook 在那之後只會少擋。
