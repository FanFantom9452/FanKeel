# 週報：每日量開關、面向與受眾篩選、提問與回覆、製作成本（10-30）

一句話：`/fankeel-weekly` 出頁時多問「顯示」，每天的工作量與製作成本預設都不出現。完成卡片可依面向與一般／技術篩選。報告底部有本週想請教的問題，從站台打開時可存回覆，之後用 `weekly.js questions` 查。

設計在 [99-archive/2026-10-30-weekly-facets-design.md](../99-archive/2026-10-30-weekly-facets-design.md)，計畫在 [99-archive/2026-10-30-weekly-facets.md](../99-archive/2026-10-30-weekly-facets.md)。上一版的決定在 [2026-10-27-weekly-skill.md](2026-10-27-weekly-skill.md)。

## 決定

- 每次出頁都問「顯示」，不設常駐預設：每天的工作量關掉時，不畫逐日提交格子，卡片不印日期，依據裡的日期也拿掉。
- 面向是設定值 `weekly.facets`，預設六個，每個標一般、技術或兩者。模型替每張卡挑一到多個，使用者在 Gate 1 改。
- 一般／技術是同一頁上的切換，不出兩份檔：技術多顯示做法、動到的模組與依據。
- 回覆只在站台打開時能存，寫回該週的歸檔 JSON 並重畫頁面；寄出的單檔唯讀。
- 同一迄日重畫時保留已存的回覆，但只限題目 id 與文字都沒變的題。
- 製作成本放頁尾、可開關，算法與 land 的花費同一個共用函式 `lib/session-cost.js`；`guard` 只對這一塊開金額例外。

## 為什麼

使用者不希望教授看到自己在哪些時段工作，所以每日量預設關，而且日期從每個出口都拿掉。教授與技術讀者要的細節不同，一頁兩種讀法比兩份檔好維護。每週的提問要能在報告當下記下回覆，之後開任務時還查得到，所以回覆存進已有的歸檔，而不是另開一個儲存處。

## 放棄了什麼

- 任務卡換算週用量與 5H 額度：等花費頁折線圖 land，另開 TODO（station-70）。製作成本那一行的額度比例先留「—%」。
- 在寄出的單檔裡存回覆：單檔沒有地方可以存。
- 日期用規則去掉，不改資料：依據裡用別種寫法寫的日期（例如「上週三」）不會被認出。
