# 花費頁分成總覽、7d 額度、5h 額度、明細四個分頁（10-31）

一句話：花費頁頂端多一排分頁，總覽看花了多少、花在哪，兩個額度分頁按帳號畫 5h／7d 額度折線並把同時段跑的 task 畫在下面，明細留原本的分項與表格；花費金額旁不再接 `(x%)`。

設計與計畫在 [99-archive/2026-10-30-spend-quota-design.md](../99-archive/2026-10-30-spend-quota-design.md) 與 [99-archive/2026-10-30-spend-quota.md](../99-archive/2026-10-30-spend-quota.md)。

## 決定

- 花費頁（`#/days`）分成總覽、7d 額度、5h 額度、明細四個分頁，所選分頁記在 hash，切換時不捲動；區間選擇四個分頁共用。
- 額度讀數多記一個 `account`，只存 `accountUuid`，不存 email 或姓名；舊讀數依 7d 重置時刻歸到帳號，兩者矛盾時以重置時刻為準。
- 7d、5h 額度分頁一次看一個帳號：上面是階梯折線，下面是 task 條。點一條 task 會反白它那段額度，並依花費比例算出它佔了多少漲幅。
- 折線上方一列寫目前百分比、照近 24 小時速度何時用完，以及每 1% 額度約等於多少美元。資料不夠時寫「資料不足」。
- 總覽只寫總花費、各帳號金額和最貴的 task，金額不接 `(x%)`；原本的分項、KPI 與表格都搬到明細。

## 為什麼

使用者在花費頁找不到 5h／7d 額度的變化，也看不出額度是被哪些 task 用掉的。這台機器有兩個帳號共用一個 config dir，用一份 `quota.week` 換算全機花費會把兩個帳號混在一起，所以改成依帳號畫額度本身，金額只寫金額。分頁讓原本一長頁的數字各有歸處，又不拿掉任何分項。

## 放棄了什麼

- 在每筆花費旁接 `(x%)`：`quota.week` 只校準了 10-29 的 6.4 小時，又拿兩個帳號的花費除以一個帳號的額度，比例不可信。它要怎麼處置另外記成 TODO。
- 把額度圖疊在原本的長頁裡：頁面已經太長，使用者說過「頁裡面還有頁」，所以改成頂端分頁。
- registry 加一個帳號欄位：改用每筆讀數自己帶的 `account`，session 歸給讀數裡最多的帳號，registry 不動。
