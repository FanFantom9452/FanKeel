# 首次使用的 init（09-30）：決策紀錄

一句話：專案第一次跑 `task.js start` 時，會先做幾項便宜的檢查。只要有一項沒過，就要求先跑 `fankeel-init` 再開始 survey。`fankeel-init` 一次問一題，把 docs tree、TODO、目錄樹、CLAUDE.md、memory 和 profile 整理好，直到 `scripts/onboard.js --full` 通過。同一個 task 還一併修了 gate-2：受控站的 gate 答過後原樣重問、沒有暫停選項、或給出低於 floor 的 class，都會被拒絕。

## 定了什麼

- **什麼時候叫**：只在專案第一次用 fankeel 時自動叫，其他時候不叫；定期清理之後再議。
  - 判斷用 hook 裡的便宜檢查：`docs.read`、未歸檔數、目錄樹區塊、`init.skip`。完整檢查（docs-check 與 drift）只在 init 本身跑。
  - 檢查對象是 task 的 project，不是 workspace 根目錄。在 Trovara 量過一次，約 71 ms。
- **跳過**：跳過會寫進 profile 的 `init.skip`，之後不再自動叫。跳過時會多出一次 gate，強烈建議先整理。
- **何謂處理完**：drift 頁要修好或封存才算處理完。
- **原始資料**：原始資料和文件分開，`docs.json` 新增 `data` 角色。docs-check、docs-audit 都不讀它，也不算進未歸檔數。
- **多 repo 的工作區**：在多個 repo 上一層開 Claude Code 時，由 scout 與 `input-check.js` 檢查會影響注入的 CLAUDE.md。
- **敏感資料**：
  - spec 與 plan 照常 commit。
  - 敏感詞清單放在 `.fankeel/sensitive.txt`，不進版控。
  - commit 時的掃描分 `sensitive.mode` 的 warn 與 block 兩種，預設 warn，先提醒、由使用者決定要不要擋。
  - 使用者要的開關是 `sensitive.review`：reviewer 要不要一併檢查敏感資料。
- **gate-2**：`readGate` 在寫入時（`hooks/gate-write.js`）和發問時（`hooks/gate.js`）都會檢查，條件是：
  - 要有暫停選項；
  - 不可低於 floor；
  - `next` 不可空。

  答過之後原樣重問也會被拒。

## 在哪裡回頭

  - 多專案一開始對準 registry 根目錄，後來改對 ProjectWorkspace 底下的 project。
  - 我原本提的 plan.commit 開關，改成 `sensitive.review`。
- **verify 退回 build 五次**：
  - 24 條失效引用、鏈式 `git add … && git commit` 會漏掃、`words()` 吞讀檔錯誤、三處過時的數量文字。
  - `-- <目錄>` 漏掃、`source.test` 被鄰居 task（promo30 v5）弄紅。
  - 新 TODO 的描述超長，以及裸路徑讓 `source.test.js` 失敗。
- **audit 找到並修掉**：
  - index 缺了兩頁、agent 數寫錯、gate 規則的描述漏了新條件。
  - brain 的 brief 沒寫暫停選項規則，是 09-30 兩次 gate 被擋的原因，已在 3e558dfb 補上。
- **沒修，留下的**：
