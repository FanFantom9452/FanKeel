# Desktop 用 Svg 畫 band 與 Pane，終端維持文字（10-15）

一句話：在 Claude Desktop 上，band 和 Pane 改成畫 Svg 圖（站點、量表、任務格、撞檔關係圖），終端照舊畫文字；兩邊的字由同一份資料產生，Svg 的 `alt` 就是終端那一列。

這延續 10-13 的[Pane 配色](2026-10-13-pane-colour.md)：標題和說明文字是灰色，顏色只用在狀態上。

## 決定

- `hooks/pane.ts` 依畫面分流：Desktop 畫 `hooks/pane-svg.ts` 產生的 Svg，終端畫 `hooks/pane-band.ts` 與 `hooks/pane-status.ts` 的文字列。Svg 畫失敗或超過引擎的字數上限時，那一塊退回文字，並記一次錯誤。
- band 第一列的最後是 Remote Control 狀態：連著時是綠色的「遠端 ✓」，沒連時是灰色的「遠端 ✗」。狀態讀自 Claude Code 自己的 session 檔，看 `bridgeSessionId` 有沒有值。列寬不夠時，它是第一個被丟掉的。
- band 的 ctx 顏色和標記照 TokenBar：依 context window 大小分檔，到門檻變紫，超過 800k 的 window 依百分比加上 ⚠、💥、💀。Pane 的 context 塊仍然以 `compact.at` 為門檻。
- context 到門檻時，band 和 Pane 都寫「已到門檻，compact 中」；`compact.at` 關掉時，提示改手動 `/compact`。

## 為什麼

- Desktop 能畫圖，終端不能。同一份資料畫兩種樣子，兩邊說的話就不會分岔。
- 自動 compact 已經存在，ctx 不再需要用顏色提醒「快到 compact 點」。使用者要的是 TokenBar 那套一看就知道 window 用掉多少的配色。
- 引擎給 mod 的介面看不到 Remote Control（`$.session.surfaces()` 開著時仍只回報 terminal），Claude Code 寫的 session 檔看得到。10-14 在 Desktop 上實測：開著時 `bridgeSessionId` 有值，關掉時是 null，沒開過時沒有這個欄位。

## 放棄了什麼

- 終端不畫圖（`Raster`、`Image`），維持文字。
- band 的 Svg 不會隨列寬縮短；窄視窗要裁掉還是縮小，等使用者在真機上看過窄視窗再決定。
- 從終端啟動的 session 有沒有寫 `bridgeSessionId` 還沒驗。從終端開 Pane 再用 Remote Control 下 `/fankeel-panel`，只有終端那邊會開關，Desktop 不會畫。
- 真機上還沒看過的有：撞檔、tasks 的滑鼠提示、淺色主題、Pane 自動開關、窄視窗。這些留在原本的 TODO 條目裡。
