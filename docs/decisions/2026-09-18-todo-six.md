# TODO 六條一起做 — 決策紀錄

使用者在 `/fankeel` 的選單上選「do it all」：`## Ready` 三條加 `## Needs a decision`
最新三條。class `architectural`，七站全走，路線 survey → design → plan → build →
verify → audit → land。分支 `todo-six`，24 個 commit 加這一站的發版。

## 一、六條不是六個 build 任務

設計的主張是按站分而不是攤平：42 對 pair 與 50 條 stale 記憶是 `audit` 的工作，
發版是 `land` 的工作，真正要寫程式與改文件的只有三條。這個分法成立——audit 那一站
確實走完了兩件，而它們在 build 裡會是兩個做不完的任務。

## 二、`gates` 存全部選項文字

TODO 給三個選項：存全部、只存被換掉的、維持現狀。**選存全部**，理由不是完整性：
`swapped` 這張卡的分母會隨 transcript 被刪而縮水，而頁面上看不出來。這是缺陷不是
缺功能。`lib/gates.js` 的 `gatesFrom()` 加 `labels`，`lib/station.js` 的
`gateSummary()` 加持久化後備，順序是 **replay 先、持久化後補**（`:454` 的
`if (!rows.length)`）。

一個真正的缺陷在整枝複審時被打出來：`clip` 會把 `answerOf` 回的 `null` 吃成 `''`，
於是沒作答的 gate 被記成「選項一被換掉」。修在寫入端（`lib/gates.js`）而不是讀取
端，因為 `''` 是合法答案——`answerOf` 對空多選就回它——只有 `null` 能表示沒作答。

## 四、量測，不是推理

這一輪最貴的教訓，同一族錯誤犯了四次，每一次都是把推出來的數字寫成量到的：

1. mutation 註解寫「紅兩條」，量出來四條。
2. 改成「改成任何其他數字都只紅這一條」——9 以下不成立（`'留在 survey'` 是 9 個
   UTF-16 單位）。
3. 改成「57 裡另外 56 綠」——其中 39 條結構上不可能紅，`lib/station.js` 從不
   `require('./gates.js')`。分母最後定在 `tests/leave.test.js` 自己的 18。
4. verify 寫 `swapped` 只讀到 89 筆的原因是「快取加了新欄位不會失效」——失效機制
   （`lib/detail.js:669` 的 `old.v !== VERSION`）存在而且有效，真正的原因是
   `8be3981` 加 `labels` 時沒把 `VERSION` 從 2 推到 3。212 份快取全帶 `v: 2`。

每一次都是複審或對手打出來的，沒有一次是自己發現的。ledger 記了一條 ruling：此後
每份複審派工單都要問「分母裡的每個檔能不能碰到被 mutate 的符號」——一個
`grep -rn "require(.*<module>"` 就答完。

同一族還有一次：ledger 的 `Fix:` 行我手打補滿了一個假 sha，`git cat-file -e` 回
no such object。`ledger.js` 只驗 7 到 40 位十六進位的形狀，假值進得了檔案。記憶
`pin-the-sha-in-recorded-evidence` 改成「永遠不要讓 sha 經過自己的文字，把
`$(git rev-parse …)` 放進命令裡」。
