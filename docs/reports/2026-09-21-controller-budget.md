# 主控佔長任務花費的 57.4%，與三專案並行的七天上限 — 2026-09-21

**這個 registry 的 44 筆長任務花掉 $3,970.46，其中 $2,280.42（57.4%）是主 session 自己燒的，$1,690.04（42.6%）才是它派出去的 agent。成分上 cacheRead 佔 56.5%——付的是重讀，不是新讀。一個七天視窗值 $3,056.00，長任務中位數 $133.34，所以一週裝得下 22 個；三個專案並行就是每個專案每週 7.3 個。主控換 Sonnet 的投影是每個專案 11.3 個，但那個投影架在一個沒人量過的假設上，見第 5 節。**

這一頁回答的是一個使用者的問題：一個任務吃掉 5h 額度的一成、7d 的 3%，那一次跑三個專案會怎樣。前一頁
[2026-09-21-quota-calibration.md](2026-09-21-quota-calibration.md) 把額度的換算做完了，
[2026-09-21-long-task-projection.md](2026-09-21-long-task-projection.md) 把換模型的投影做完了；
這一頁補的是中間那一格——**錢在主控還是在 agent**，以及換算成「幾個任務」之後長什麼樣。

## 1. 分母

`.fankeel/sessions` 掃到 **182** 個 entry，0 個讀不出來，其中 **81 個帶 `spend` 欄位**，101 個沒有。`requests` 在 200 以上的有 **44 筆**——桶的邊界由 `lib/spend.js` 自己的 `buckets` 決定，本頁沒有複製它。

**單位是 session，不是 task。**一個任務若跨了兩個 session，它在這裡就是兩筆。

逐站那一塊有一個 `<synthetic>` 的模型 id 沒有費率。它的 token 被排除在美元之外，不是當成零——這一點跟
[2026-09-21-long-task-projection.md](2026-09-21-long-task-projection.md) 第 6 節處理的是同一個東西。

## 2. 錢在主控那一半

| 這一半 | usd | 佔比 |
|---|---|---|
| parent（主控自己） | $2,280.42 | **57.4%** |
| subagents | $1,690.04 | 42.6% |
| 合計 | $3,970.46 | 100.0% |

| 成分 | usd | 佔比 |
|---|---|---|
| input | $0.70 | 0.0% |
| output | $854.99 | 21.5% |
| **cacheRead** | **$2,243.93** | **56.5%** |
| cacheWrite | $870.84 | 21.9% |

`input` 幾乎是零而 `cacheRead` 過半，這兩件事是同一件事：長 session 的每一輪都把整份 context 重送一次，而那一份幾乎全部命中快取。**錢跟著 context 的長度乘上輪數走**，不是跟著讀了多少新東西走。

## 4. 七天視窗裝得下幾個長任務

這一節的基礎 **n = 2**，而且沒有辦法變大：額度的水位只出現在 statusline payload 裡，那個檔被每一次 render 覆寫，兩份捕捉是因為有人在下一次 render 之前把它複製走了。這一節推出來的每一個數字都繼承那個 n。

| 讀數 | 5h | 7d | 那個 session 自己的 usd |
|---|---|---|---|
| A　2026-09-20T16:30:41Z | 2% | 0% | $12.56 |
| B　2026-09-20T20:35:15Z | 13% | 3% | $109.11 |

兩次之間的那一段五小時視窗，含裡面每一個 session：**760 個 request、1.59 億 token、$91.68**。用它而不是用任一份捕捉的 `cost.total_cost_usd`，是因為後者是那一個 session 自己的數字，而視窗裡有兩個 session——那份捕捉檔的註腳自己寫了這件事。

計量移動了 5h **11** 點、7d **3** 點，於是：

| | |
|---|---|
| 一個 5h 視窗值 | **$833.45** |
| 一個 7d 視窗值 | **$3,056.00** |

全機 `800+` 桶的長任務中位數是 **$133.34**（29 筆，11 個 registry，cacheRead 佔 61.6%）。所以：

| | |
|---|---|
| 7d 視窗裝得下 | **22 個長任務** |
| 三個專案分完 | 每個專案每週 **7.3 個** |
| 5h 視窗裝得下 | 6 個 |

**先撞到的是 7d，不是 5h。** 三個專案同時各跑一個長任務是 `3 × $133.34 = $400`，對 $833.45 的五小時格子是 48%，過得去；但七天的格子只有一個，而且是全帳號共用的——這台機器上有 11 個 registry，它們分的是同一格。「三個專案」不是三份預算。

中位數是全機的，主控佔比是這個 registry 的。兩個分母不同，混用是這一節唯一的近似。

## 5. 換 Sonnet 主控：算得出來的那一半

`lib/prices.js` 的 Sonnet ÷ Opus，四個分量全部等於 **0.4**——腳本是算出來的，不是寫死的。所以在 token 量不變的前提下：

| | |
|---|---|
| 主控佔比 | 57.4% |
| 中位數會變成 | **$87.39** |
| 7d 裝得下 | **34 個** |
| 三個專案分完 | 每個專案每週 **11.3 個** |

**「token 量不變」是這一節唯一的假設，而它沒有被量過。**
[2026-09-21-long-task-projection.md](2026-09-21-long-task-projection.md) 把破平衡點算成 `k = 2.5052`：Sonnet 要在沒有站 agent 的那些站上燒掉超過 2.5 倍的 token，換主控才會變貴。2.5 倍是很寬的餘裕，但餘裕不是量測。

所以這一頁對主控模型的主張只有一句：**這是一個可以一行指令切回去的設定，不是一個要先證明的架構。**

## 6. 這一頁不主張的

- **不主張 `stage.agents` 該預設打開。** 唯一量過的那一站打平，而打開 build 會讓主 session 在整個 build 期間不能改檔，其中 build 站 agent 需要的 workflow 產生器此刻還不在 repo 裡。
- **不主張 57.4% 全部省得下來。** 主控就算只剩派工、轉路徑、問關卡，它仍然有一份 context 在成長，仍然要付 cacheRead。省下來的是差額，不是那一整塊。
- **不主張 22 與 34 是預測。** 它們是「以中位數計，這個格子裝得下幾個」，而長任務的分佈很寬。中位數 $133.34 與總額 $5,126.26 除以 29 筆得到的均值差了一截，那個差就是分佈的形狀，兩個數字都在 block 4 裡。
- **不量 fankeel 自己的注入。** 每站的注入區塊上限 2,400 字元，實測 2,254–2,396，相對於一輪 25 萬 token 的 cacheRead 是 0.1% 等級。它不是這一頁在找的東西。
