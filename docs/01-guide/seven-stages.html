時間大多花在等人，不是等機器。

一件任務怎麼走：點節點跳到那一段

上排是八個停靠點，每段結束都停在關卡問你；下面三條線是三種分類，各只停它路線上的段。

architectural
新子系統，或改到別處依賴的介面。七段全走；白板任務走這條。
bounded
既有流程裡的範圍內修改。design 在對話裡完成，不寫 spec 或 plan，只留 handoff。
spike
可行性問題，產出是一個答案；做出來的東西標為可丟。
  • 關卡：段落結束，用選項問你下一步
  • 退回：VERIFY 發現缺口，回 BUILD 補做
  • 主線：做完交棒

分類只升不降：途中發現比想的複雜，就用 task.js route 換到較重的線，並說出來。

每一段的裡面：跑哪支腳本、派哪個代理

以 .js 結尾的是 scripts/ 的腳本，fankeel- 開頭的是子代理，hooks/ 底下的是 hook；沒有程式名的那步，是主 session 自己做或問你。

INIT 第 0 步

每件任務都從這裡進

  1. hooks/inject.js每則提示注入 session id、監控站網址與規則
  2. orient.js看現場：專案、分支、髒檔、TODO 摘要，什麼都不寫
  3. task.js show自己有沒有任務、別人在做什麼、有沒有交接
  4. 問你用選項問要做哪件，選項取自 TODO 標題；講清楚了就跳過
  5. task.js start寫進 registry 與狀態列；--todo 綁定 TODO 條目
  6. fankeel-init只在第一次用、印出 onboard: 時跑：整理 docs、TODO、CLAUDE.md

不設關卡：登記好就在同一回合進 SURVEY

SURVEY 一份現況事實

走這段：architectural、bounded、spike

  1. map.js先讀專案自己的文件地圖：哪些現行、計畫了沒做、已退役
  2. survey.js <詞>直接讀工作樹找命中，每筆附 path:line
  3. fankeel-reader範圍大才派：一題一位，同一則送出
  4. context.js add記下事實、path:line 與 commit，後段不再重查
  5. task.js route分類 spike／bounded／architectural，只升不降
  6. 寫報告發現、計畫未做、沒找到、不知道、跳過，各一欄

關卡：要進 DESIGN 嗎？

DESIGN 你同意的做法

走這段：architectural、bounded

  1. 一次問一題目的、限制、成功標準；能給選項就給選項
  2. 一個做法附取捨；先問不需要？已經有？標準庫或平台有？
  3. fankeel-mockup會上畫面才派：用專案的 CSS 畫一頁，render.js 截圖、design-lint.js 掃樣式
  4. tune.js serve開這頁讓你點一塊寫一句，代理只改那一塊
  5. 完成標準一條現在會失敗、做完會通過的檢查
  6. .fankeel/map.md對照地圖：碰到哪頁文件、有沒有矛盾
  7. specarchitectural 才寫進計畫目錄；bounded 只在對話裡講

關卡：核准這個做法（選項一寫明內容）

PLAN 分好組的任務

走這段：architectural

  1. ## Task N固定模板：讀哪些、改哪些、先寫的測試、Dispatch
  2. 約束從 map、CONTRIBUTING、package.json 產生，不靠記
  3. ledger.js groups依深度分組：同一層彼此不衝突，可一起派
  4. Coverage 表設計的每條承諾都對到一個任務
  5. ledger.js lint模板有沒有空格、有沒有佔位字
  6. fankeel-reviewer專挑毛病：沒有任務的承諾、Files 對不上
  7. task.js intends宣告要改的檔，看別的 session 有沒有在改

關卡：核准計畫，開始 BUILD？

BUILD 提交好的成品

走這段：architectural、bounded、spike；中途不停下來問

  1. hooks/guard.js範圍守衛：別的 session 佔用的檔就擋或問
  2. ledger.js ready列出現在能開工的組與任務
  3. fankeel-implementer一任務一個 worktree：先寫測試，再寫最少的程式
  4. fankeel-reviewer逐任務審 diff；有畫面再加 fankeel-render-reviewer
  5. commit.js提交一個任務；ledger.js complete <n> 記進帳本
  6. docs-moved.js修好行號移動的引用，剩下的交 fankeel-fixer
  7. suite.js --fast全套跑一次，只回報決定成敗的兩行

關卡：要進 VERIFY 嗎？BUILD 只問這一次

VERIFY 對過的證據

走這段：architectural、bounded

  1. 證據表設計與計畫的每條承諾一行，標 held／failed／未檢查
  2. fankeel-verifier每任務一位、平行派；證據寫進檔案，只回路徑
  3. suite.js --fastbuild、test、lint 有宣告的都跑，貼真實輸出
  4. docs-check.js這次改動讓哪些文件不再正確
  5. fankeel-mutator故意改壞一行，看測試變紅，再還原
  6. fankeel-render-reviewer有畫面時，截圖對照核准的 mockup
  7. fankeel-reviewer當反方：專挑證據沒證到的地方，含資安

關卡：證據夠了？不夠就退回 BUILD

AUDIT 一份殘留清單

走這段：architectural

  1. docs-check.js斷連結、超出檔尾、宣告不存在、引文變了
  2. residue.js沒人決定的檔、沒清的 worktree 與分支、空目錄
  3. docs-audit.js落後的頁、做完沒封存的計畫、索引缺漏、孤兒頁
  4. memory-check.jsClaude Code 的記憶還指向真的東西嗎
  5. input-check.js每個 session 都載入的檔有多大、哪些能砍
  6. knip／deptry沒用到的依賴與匯出；沒裝就寫「沒跑」
  7. fankeel-reader候選真的打開來讀；斷參照交 fankeel-fixer 修

關卡：要清哪些檔？選項一寫明，不擅自搬或刪

LAND 已整合的成果

走這段：architectural、bounded

  1. suite.js --check全套必須全綠，而且是這棵樹上跑的紀錄
  2. skills-check.jsskill 提到的腳本與旗標都還存在
  3. record.js write先寫完成紀錄：要求、交付、花費
  4. todo.js done關閉來源條目，附紀錄與 commit；再跑 todo-check.js
  5. version.js只有你說這是一次發版，才改版號
  6. map.js重寫地圖，下一件任務從這裡開始
  7. task.js land依 land.integration 合併、開 PR 或保留分支；沒設就給你選單

關卡：收工、開新任務，或匯出並回顧

每段收尾都一樣：fankeel-brain 把報告寫進 .fankeel/build/task-*/，主 session 用 await.js 在背景等它，關卡問句逐字照抄（hooks/gate.js 核對），你答完才 task.js stage 進下一段。

BUILD 的裡面：分組、派出、收回，最後才問一次

每個就緒的組派一個 build 代理（build group <n>）；沒有組可派、任務都完成時，再派一個 build close 修文件、跑全套測試並寫關卡。

白板任務
