# 極小實驗 mod 的四項實測 — Implementation Plan

**Goal:** 在本 session 的 dev-mods 資料夾寫一個不進 repo 的實驗 mod，由使用者與主 session 依 M0 到 M5 實際跑一次，再把記錄與 mod 原樣存進 repo、寫成一份四項判定的量測報告。
**Architecture:** Task 1 寫 mod 的三個檔（`plugin.json`、`hooks.json`、`probe.ts`），每個 hook 觸發寫一個單行 JSON 記錄檔到 `.fankeel/build/task-20261003T023224/mod-probe/`；只有 `prompt.compose`、`agent.spawn`、`turn.step` 三處改寫，而且只動帶 `mod-probe` 標記的派遣。Task 2 是使用者與主 session 的步驟：熱重載開關只有使用者按得到，子代理必須從主 session 派，量到的才是主 loop 的 `agent.spawn`（spec 第 7 節）。Task 3 把記錄、mod 與五個探測子代理的 transcript 複製到 `docs/90-agent/reports/evidence/<量測日>-mod-probe/`，照 spec 第 3 到第 6 節的規則判定，寫報告並替 design、plan、報告三頁加 `docs/README.md` 索引列。
**Tech Stack:** Claude Code 2.1.288 的 function-hook plugin（mod）API，型別權威檔 `C:/Users/Owner/AppData/Local/Temp/claude/bundled-skills/2.1.288/2e2cabe37e78a1318b6edaff92390520/plugin-authoring/types/claude-code.d.ts`（下稱 d.ts）；mod 在沒有 Node 的環境執行，對外一律經過 `$`。repo 端只用 Node 24 內建模組與 `node --test`。
**Spec:** [2026-10-03-mod-probe-design.md](2026-10-03-mod-probe-design.md)

用語：「量測日」是 Task 2 的 M0 那天，寫成 `YYYY-MM-DD`，由 Task 3 從 `session.start` 記錄的 `at` 換算（本機時區）。下文路徑裡的 `<量測日>` 都指它。

## Global Constraints

- 不得新增相依套件：`package.json` 沒有任何 dependency，`npm test` 就是 `node --test`。
- repo 根目錄沒有 `CLAUDE.md`；慣例取自程式碼本身：JS 檔第一行 `'use strict';`、`lib/`、`scripts/`、`hooks/` 用 4 格縮排。
- `.gitattributes` 是 `* text=auto eol=lf`：寫 LF。
- 歸檔（`.fankeel/map.md` 的 filing）：`docs/90-agent/reports` 是 report、`docs/90-agent/reports/evidence` 是 fixture、`docs/90-agent/plans` 是 plan，索引是 `docs/README.md`。evidence 不進索引（`docs/README.md:384`）；report 與 plan 要有索引列。
- report 頁照先例 `docs/90-agent/reports/2026-09-28-subagent-hook-probe.md:1-5`：frontmatter `status: current`、`last_verified`、`source_of_truth`，跑一次就不再更新；以繁體中文書寫（profile `language`）。
- 實驗 mod 不進 repo，也不改 fankeel 的任何 hook、agent 檔、`lib/` 或 `.claude-plugin/`（spec 第 1 節）。
- evidence 資料夾裡不放任何 `*.test.*` 檔：`node --test` 會把它當測試跑。
- implementer 只跑自己 task 寫的檢查，不跑全套；全套由派它的 brain 在 commit 前跑。

## Risks

- Task 1 只寫 repo 外的 dev-mods 資料夾，它的 worktree 沒有任何追蹤中的變動，commit 區塊可能是空的 — Task 1 — brain 收到它的回報後先 `git -C <worktree> status --porcelain`，空的就照實寫進 commit 區塊並由 `scripts/commit.js` 回報；這不是 implementer 的錯。
- 使用者 task 排在兩個派遣 task 之間，與 fankeel-plan skill「user task 放最後、派遣 task 不得依賴它」的規則相反；這是 spec 第 7 節的明文要求 — Task 3 — Task 3 的 `Consumes:` 引用 Task 2 的 `Produces:`，`ledger.js ready` 在 Task 2 記為 complete 之前不會列出 Task 3；brain 做完 Task 1 就交回，主控與使用者跑 Task 2、`ledger.js complete 2`，再派新的 brain 做 Task 3。
- `claude plugin validate` 可能拒絕同一個 `hooks.json` 裡的 `hooks` 鍵 — Task 1 — implementer 不自行拿掉它，原樣回 `blocked:` 附上 validate 的輸出：那本身就是 (d) 的一半答案，要不要拿掉由使用者決定。
- 主 session 若在 M4 結束前讀過任何記錄檔的內容，nonce 就進了它的 context，M1 的引用不再是盲測 — Task 2 — M0 到 M4 只用 `ls`，以及只印出 `agentId` 與 `hasFankeel` 兩個欄位的 `grep -o`，不 `cat`、不 Read 記錄檔。
- fankeel 的 `hooks/brief.js` 會在子代理的任務文字之前插入 hook-context 列，「首則訊息」未必是任務 prompt — Task 1 — `turn.step` 掃的是第一則 assistant 之前的所有 user 列，而不只第一則；這是對 spec 第 5 節「讀第一則」的收窄，目的相同。
- 量測日不是今天也行：路徑一律由 Task 3 從記錄換算，不寫死日期 — Task 3 — 第一步先算出量測日，之後每一步都用它。

```ts
import type { Register, EngineInterface } from 'claude-code'

// 一次性量測 mod（docs/90-agent/plans/2026-10-03-mod-probe-design.md）。
// 每次 hook 觸發寫一個單行 JSON 記錄檔；$.fs.write 只能整檔寫入，所以一事件一檔，
// 檔名依時間排序就是事件順序。只有三處改寫，而且只動帶 mod-probe 標記的派遣。
const LOG = 'F:/ymlab/fankeel/.fankeel/build/task-20261003T023224/mod-probe'
const EFFORT = /MOD-PROBE-EFFORT=(low|medium|high|xhigh)/

let nonce = ''
const effortOf = new Map<string, string | null>()

// 啟用與熱重載都會讓 session.start 再跑一次（d.ts:4057），模組變數也會清空；
// nonce 存在 $.store，沿用舊值才不會中途換號。
async function getNonce($: EngineInterface): Promise<string> {
  if (nonce) return nonce
  const kept = await $.store.get('probe.nonce')
  if (typeof kept === 'string' && kept) {
    nonce = kept
    return nonce
  }
  const fresh = crypto.randomUUID()
  await $.store.set('probe.nonce', fresh)
  nonce = fresh
  return nonce
}

function suffix(): string {
  return Math.random().toString(36).slice(2, 6).padEnd(4, '0')
}

// 寫失敗不讓 hook 失敗：hook 一失敗就被跳過，連帶丟掉它的改寫。
async function record($: EngineInterface, event: string, fields: Record<string, unknown>): Promise<void> {
  const at = Date.now()
  const name = `${String(at).padStart(13, '0')}-${event}-${suffix()}.json`
  try {
    await $.fs.write(`${LOG}/${name}`, JSON.stringify({ event, at, ...fields }) + '\n')
  } catch (err) {
    $.ui.log(`fankeel-mod-probe: ${event} record not written: ${String(err)}`)
  }
}

function textOf(content: unknown): string {
  if (typeof content === 'string') return content
  if (!Array.isArray(content)) return ''
  return content
    .map((b: { type?: string; text?: string }) => (b && b.type === 'text' && typeof b.text === 'string' ? b.text : ''))
    .join('')
}

export const register: Register = (on) => {
  on('session.start', async ($, e, next) => {
    const n = await getNonce($)
    await record($, 'session.start', { nonce: n, isInteractive: e.isInteractive })
    return next(e)
  })

  // 改寫一：系統提示尾端加一段固定的被動標記，scope 為 session，放在所有 shared 之後。
  on('prompt.compose', async ($, e, next) => {
    const n = await getNonce($)
    await record($, 'prompt.compose', {
      model: e.model,
      promptModel: e.promptModel,
      traits: e.traits,
      tools: e.tools,
      surfaces: e.surfaces,
    })
    const out = await next(e)
    return {
      ...out,
      sections: [
        ...out.sections,
        { id: 'fankeel-mod-probe:marker', text: `MOD-PROBE-COMPOSE-${n}：量測標記，不需理會。`, scope: 'session' as const },
      ],
    }
  })

  // 改寫二：只對 description 含 "mod-probe b" 的派遣，在 prompt 尾端加一行。
  // 加在尾端，因為 hooks/brief.js:95 的 stageOfPrompt 靠 prompt 的第一個字判斷站名。
  on('agent.spawn', async ($, e, next) => {
    const n = await getNonce($)
    const isB = e.description.includes('mod-probe b')
    const prompt = isB ? `${e.prompt}\nMOD-PROBE-SPAWN-${n}` : e.prompt
    const startedAt = Date.now()
    const res = await next(isB ? { ...e, prompt } : e)
    await record($, 'agent.spawn', {
      startedAt,
      tool_use_id: e.tool_use_id,
      description: e.description,
      subagentType: e.subagentType,
      parentAgentId: e.parentAgentId ?? null,
      promptLengthBefore: e.prompt.length,
      promptLengthAfter: prompt.length,
      agentId: res.agentId ?? null,
      model: res.model ?? null,
      deny: res.deny ?? null,
    })
    return res
  })

  // 改寫三：子代理的請求，若它第一則 assistant 之前的 user 列帶 MOD-PROBE-EFFORT=<level>，
  // 就把 effort 改成該等級。串流事件，只能寫成 async function*（reference.md:28-30）。
  on('turn.step', async function* ($, e, next) {
    let effort = e.effort
    let note: string | null = null
    if (e.agentId !== undefined) {
      let level = effortOf.get(e.agentId)
      if (level === undefined) {
        const found = await $.session.messages({ agentId: e.agentId })
        if (!Array.isArray(found)) {
          note = `messages denied: ${String((found as { deny?: string }).deny)}`
        } else {
          const head: string[] = []
          for (const m of found) {
            if (m.role === 'assistant') break
            head.push(m.text)
          }
          if (head.length) {
            const hit = EFFORT.exec(head.join('\n'))
            level = hit ? hit[1] : null
            effortOf.set(e.agentId, level)
          }
        }
      }
      if (level) effort = level as typeof e.effort
    }
    const result = yield* next(effort === e.effort ? e : { ...e, effort })
    await record($, 'turn.step', {
      agentId: e.agentId ?? null,
      index: e.index,
      model: e.model,
      effortBefore: e.effort ?? null,
      effortSent: effort ?? null,
      outputTokens: result && result.usage ? result.usage.output_tokens : null,
      note,
    })
    return result
  })

  on('classic.SubagentStart', async ($, e, next) => {
    await record($, 'classic.SubagentStart', { agent_id: e.agent_id, agent_type: e.agent_type })
    return next(e)
  })

  // 只記 hook-context 列：fankeel 的 command hooks（inject.js、brief.js）的輸出從這裡進來。
  on('session.append', { door: 'hook-context' }, async ($, e, next) => {
    const text = textOf(e.message.content)
    await record($, 'session.append', {
      agentId: e.agentId ?? null,
      origin: e.origin,
      head: text.slice(0, 80),
      hasFankeel: text.includes('FANKEEL'),
    })
    return next(e)
  })
}
```

```js
'use strict';

// 從主 session 的 transcript 抄出 M1 那一問一答：以 "MOD-PROBE M1" 開頭的使用者
// prompt，以及回答它的 assistant 列。讀過 plan 的 tool_result 也含這串字，
// 所以只認真正的 prompt（不是 tool_result、不是 isMeta），並取最後一次。
const fs = require('node:fs');

const [src, dest] = process.argv.slice(2);
const lines = fs.readFileSync(src, 'utf8').split('\n').filter(Boolean);
const rows = lines.map((l) => { try { return JSON.parse(l); } catch (e) { return null; } });

const textOf = (r) => {
    const c = r && r.message && r.message.content;
    if (typeof c === 'string') return c;
    if (Array.isArray(c)) return c.filter((b) => b && b.type === 'text').map((b) => b.text).join('\n');
    return '';
};
const isPrompt = (r) => Boolean(r) && r.type === 'user' && !r.isMeta
    && !(Array.isArray(r.message && r.message.content) && r.message.content.some((b) => b && b.type === 'tool_result'));

let start = -1;
rows.forEach((r, i) => { if (isPrompt(r) && textOf(r).trimStart().startsWith('MOD-PROBE M1')) start = i; });
if (start < 0) {
    console.error('no MOD-PROBE M1 prompt in ' + src);
    process.exit(1);
}
const out = [lines[start]];
for (let i = start + 1; i < lines.length; i++) {
    if (isPrompt(rows[i]) && textOf(rows[i]).trim()) break;
    if (rows[i] && rows[i].type === 'assistant') out.push(lines[i]);
}
fs.writeFileSync(dest, out.join('\n') + '\n');
console.log('m1 rows: ' + out.length);
```
