# mod 探測第四輪：(d) mod 載入時，fankeel 的 command hook 內文沒有被干擾（兩臂對照，n=1）

## 判定

沒有干擾：mod 臂的請求本文裡，受控 stage 區塊與 reader 的 FANKEEL 第一行都照常送到，和對照臂一樣。判定只看 proxy 存下的請求本文與 debug 檔，不看模型怎麼說。

第三輪把這一項判為「未測」，因為補測的 session 沒有 `sessions/` 檔、`task.js` 拒絕它（[mod-probe-3](2026-10-03-mod-probe-3.md) 的 (d) 一節）。`7d63b578` 之後 `task.js` 也接受環境變數證明的 session（`lib/live.js:151-159`），這一輪因此能進受控 stage。

## 怎麼量

- 兩臂都是在 repo 根目錄新開的互動式 session，`ANTHROPIC_BASE_URL` 指向證據資料夾的 `proxy.js`，每個請求本文存進該臂的 `bodies/`。
- 對照臂不帶 `--plugin-dir` 與 `--settings`；mod 臂帶第三輪的 `mod/` 與 `settings.json`。mod 有沒有載入，以 `debug.log` 裡的 `hooks module fankeel-mod-probe@inline loaded` 為準。
- 兩臂都貼同樣三則 prompt（證據資料夾的 `prompts.txt`）：先 `task.js start --route survey` 進受控 stage，下一則才派一個 `fankeel:fankeel-reader`，最後 `task.js down`。
- `judge.js` 在主 session 的本文裡找 `FANKEEL ACTIVE — mod-probe d @ survey`（`inject.js` 的受控 stage 區塊），在 reader 的本文裡找 `FANKEEL — you are a subagent of: mod-probe d @ survey`（`brief.js` 的第一行）。對照臂兩樣都找得到，量測才算數。
