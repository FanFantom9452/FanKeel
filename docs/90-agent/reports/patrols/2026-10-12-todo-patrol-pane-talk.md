- Pane 多了一行探測：設了環境變數 `FANKEEL_PANE_PROBE` 才畫，內容是引擎說這個 session 畫在哪些地方。它是為了回答「Pane 能不能顯示 Remote Control 有沒有開」。
- 14 條 Blocked 的條件都沒到，日期重蓋成 2026-10-12；其中一條引到不存在的頁，改引到現在的頁。
- 給人看的三頁跟著改了：README 講 Pane 的那一句，以及 guide 裡 profile 與 station 兩頁各一段。

- 沒有人在真的畫面上看過這一輪的 Pane 與對話分頁：verify 沒有派 render reviewer，專案也沒有 `.fankeel/render.json`。
- 沒有跑 red-green 的部分：重蓋日期與 README 那一個 task，以及真機那一個 task。

## 為什麼

- verify 走了三輪，前兩輪各把東西送回 build。第一輪抓到 guide 的兩句：一句把「滿 20 分鐘」寫成「超過 20 分鐘」，一句長到 225 欄。第二輪的 reviewer 抓到一個程式問題：紀錄檔存在但讀不到時，伺服器和「沒有紀錄檔」回同一個狀態碼，分頁因此說成檔案不見了、也不給重試。計畫本來就把兩種情況寫成同一個狀態碼，所以改掉它是偏離計畫，ledger 記了一條 ruling。
- 第二輪的 adversary 指出四個 task 的測試沒有人證明過會變紅。第三輪補跑了 9 個改壞程式的實驗，連同第二輪的 4 個，共 12 個會讓點名的測試變紅。
- 剩下 1 個不會變紅：把「重畫時不再抓一次」的那個判斷拿掉，測試不是失敗，而是跑不完。使用者在關卡接受照原樣留著；代價是那裡壞掉時，看到的是整套測試停不下來，而不是一個有名字的失敗。
- 計畫的風險段有一句說「兩種壓縮分隔線帶同一個識別字」，實際只有帶摘要的那一種有。兩種各有測試守著，所以判定是計畫用詞不準，不是程式行為有錯。
- 整套測試要把 `FANKEEL_BROWSER` 設成 Chrome 執行檔的完整路徑才會全綠。只寫 `Chrome` 這個字時它不是路徑，程式會改用 Edge，而這台機器上的 Edge 不會寫出截圖，14 個繪圖測試會紅。最後一次是 4085 過、0 失敗。
- 這一輪中途換過 session：第一輪 verify 之後交接，新的 session 接手做完剩下兩輪與收尾。
