# TODO 四條＋tune live — 決策紀錄

使用者在 `/fankeel` 的選單上答「do it all」：`## Ready` 一條、`## Needs a decision` 三條，`## Waiting` 不動。design 關卡又追加第 5 條（真實頁面逐塊調），build 關卡再追加 §6。計畫與設計在 `docs/99-archive/2026-09-24-todo-four.md`、`docs/99-archive/2026-09-24-todo-four-design.md`。

## 決定了什麼

- **description 的格式是 `<別名> <版本> · <effort>: <標題>`**；沒釘 effort 的 agent 寫 `inherit`，不猜數字（使用者選）。規則要同時寫進 `agents/fankeel-brain.md` 與 `renderBrainBrief`，因為站 agent 不讀 `skills/fankeel/SKILL.md`——只寫 skill 那一版，brain 派出去的標題照舊，是使用者在 build 中看標題發現的。
- **gate 的問法分三種**：stage gate 三選項、要比對內容的單選帶 `preview`、`multiSelect` 不帶。規則放 skill、驗證放 `gateProblem`，不進 `ALWAYS`，不佔每輪注入額度（使用者選）。
- **station 答 gate 靠 hook 代答**：PreToolUse 回 `allow` 加 `updatedInput.answers`，終端的卡片就不出現。這是互動實測來的——`claude -p` 沒有 `AskUserQuestion`，站 agent 跑 `claude -p` 又被分類器擋；第一次被擋時站 agent 把 verdict 寫成 failure，主控改回 unmeasured，才沒把沒測過的東西寫成「做不到」。做成 `gate.station`，預設 off。
- **逐塊調走真頁面，不走假資料**：mockup 只定方向。第一版 live 模式送靜態副本、攔下每個 click、只認 `data-block`，使用者看了說「只有一頁、互動全不見、只能選大區塊」；改成 `--proxy` 真 station、Alt+click 才選、任何元素可選、class 名也能找回原始碼。mockup 要 `<link>` 專案真的 CSS、從真 DOM 起稿（使用者提的方向）。
