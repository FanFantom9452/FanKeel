# 盤點檢查補上兩個漏洞：在本 session 跑的盤點，和手寫的 TODO.md

一句話：0.111.16 的盤點檢查只管得到「一條一個檔的 TODO、交給階段代理跑的 survey」，這次補上另外兩種情況——在本 session 直接跑的盤點，和手寫的 TODO.md——兩種都會在報告漏掉條目時擋下關卡。

前一份報告在 [patrols/2026-10-17-todo-patrol-every-entry.md](2026-10-17-todo-patrol-every-entry.md)。

## 做了什麼

- 在本 session 跑的盤點 survey，要先把報告寫到階段代理會寫的同一個位置（`.fankeel/build/task-<started>/survey.md`），再問關卡。`hooks/gate.js` 看到關卡（第一個選項寫著 `plan`）時會讀這個檔：沒有檔，或漏了任何一條，就擋下並說要寫到哪裡。中途問的其他問題不檢查。這是 design 時和使用者選定的做法。
- 手寫的 TODO.md 沒有編號，所以改用標題比對：每條取它的第一句，和 `migrate` 轉成檔案時取的標題一樣。報告照原樣抄條目（帶反引號或連結）也算點到。
- verify 的對抗審查跑了四輪，每輪都退回 build。這樣一路補上了：一行只算一個條目（一行寫兩條、標題包在另一個標題裡、兩條同標題，都會少算一條）；處置詞要在拿掉名字後的文字裡找，所以「Keep docs in sync」這種標題不會自己給出 `keep`；報告只看關卡區塊以上的內容。
- skill 段落和 subagents.md 的關卡那一列，都拿掉了「只涵蓋兩種情況」的說明。

## 沒做什麼

- 標題短到像 `do` 這種、剛好是處置詞一部分的情況，可能會誤擋；這種標題太刻意，沒處理。
- 手寫 TODO.md 裡的勾選框 `[ ]` 和子項目，照 `lib/todo.js` 本來的讀法算，不另外處理。
- 在本 session 時，「這題是不是關卡」只看第一個選項有沒有寫 `plan`，和原本「關卡選項不足三個」的提醒用同一套判斷。
