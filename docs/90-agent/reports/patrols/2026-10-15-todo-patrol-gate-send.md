## 起因

使用者在開任務時選了「TODO 全表盤點」。survey 逐條核過 31 筆：Ready 6、Needs a decision 0、Blocked 13、Watch 11（其中一筆 Blocked 帶兩個條目）。Ready 的 6 筆裡，這個 session 做得了的只有站上 gate 那一筆，其餘五筆都要使用者在 Claude Desktop 或終端前面。

## 做了什麼

- 站上 gate 選項點下去要有回應：選項、交給終端和送出答案按下去後，按鈕停用並顯示送出中…；成功就維持停用，伺服器拒絕、網路錯誤或十秒沒回應就把按鈕還回來，網路錯誤和逾時會說可以再按一次。狀態跟著那一個 gate 存，所以每三秒重畫頁面不會把按鈕變回可按，下一個 gate 重新開始。build 走了三輪修正：第一輪補上「下一個 gate 被上一次送出鎖住」和「送出中…被樣式藏起來」，第二輪補上「勾選答案會把送出答案重新打開」，第三輪把三個字串的 key 改成它所在區段的前綴。整套 4260 個測試通過。
- 接縫「在哪提交」：使用者決定 commit.js 照它所在目錄的 repo 提交是設計，任務的 project 不是目前目錄時是已知限制，寫進子代理說明頁後結案。
- drive.js 第一次實跑：使用者選了第一個交給它的任務是小型文件或測試任務，用 `--max-rounds 2 --max-usd 2`，條目移到 Ready。
- 十一筆 Blocked 條件都沒到，重新蓋章 2026-10-15。
- 整套測試偶發紅燈的兩筆照使用者的決定繼續觀察，不動。

## 沒做什麼

- 五筆 Ready 要使用者的真機，留在 Ready：子代理 brief 改走 spawn、Desktop 真機看壓縮視窗、實測安裝版 mod 啟動就載入、面板真機沒看完的四件事、終端啟動讀遠端狀態。
- 站上 gate 的條目要求「實際打開真的站上頁面看過」。verify 的關卡掛在站上頁面讓使用者作答，但沒有紀錄顯示答案是從頁面還是從終端送出的，所以按鈕在真的頁面上長什麼樣子，還沒有人確認過。
- 停用按鈕和送出中的樣式沒有測試，只有程式碼審查讀過。
